# 动作游戏设计指南

本指南用于回答：**除了打击感，动作游戏还需要设计什么，以及应该按什么顺序验证这些设计。** 适合在立项、原型开发和版本评审时使用，尤其适合以近战、闪避和敌人交锋为核心的小型项目。

动作游戏的核心是让玩家在时间和空间压力下做出选择，并理解选择的结果。打击感帮助玩家感知结果；移动、战斗规则、敌人和关卡负责让这些选择值得反复进行。建议先验证最小战斗循环，再逐步加入成长、内容和长期目标。

本文是一份设计工作指南，不是带有实证结论的行业调研报告。各项验收方法用于发现问题，具体参数需要结合项目视角、平台和目标玩家测试。

## 1 使用方式与设计范围

1. 立项时，填写第 2 节的项目定义，明确体验目标与范围。
2. 开发时，按第 5 节的阶段顺序推进，为当前阶段选择必要模块。
3. 设计具体动作、敌人和关卡时，使用第 6 节的记录模板。
4. 每轮试玩后，按第 7 节复盘，记录证据、修改和复测结果。

**优先级约定：**P0 是验证核心体验的必要项；P1 是核心循环成立后增加的深度与变化；P2 是根据产品目标决定的扩展。优先级不是固定排期，例如平台跳跃项目应把跳跃置于 P0，联机项目需要尽早验证网络条件下的基础交互。

### 玩法方向如何影响设计重点

下面列出的是可组合的玩法方向，并非互斥的类型分类。

| 玩法方向 | 玩家反复进行的行为 | 优先验证 |
| --- | --- | --- |
| 近战交锋 | 观察、接近、攻击、回避 | 攻击承诺、距离、打断、防御时机 |
| 连招与风格评分 | 衔接动作、切换武器、追求表现 | 取消规则、连招空间、评分与重复惩罚 |
| 平台移动 | 跳跃、攀爬、冲刺、避险 | 起落手感、容错、落点判断、镜头 |
| 群战与清版 | 控制位置、处理多个威胁 | 敌人分工、攻击配额、脱围手段 |
| 潜行动作 | 观察、绕行、制造机会 | 视听感知、警戒状态、信息与路线 |
| 动作 RPG | 战斗、获取奖励、调整构筑 | 操作与数值的关系、成长选择、掉落 |
| 高风险探索 | 谨慎推进、学习敌人、管理资源 | 检查点、失败成本、捷径、资源压力 |

## 2 先写清楚项目要带来的体验

在添加技能、装备或地图之前，先用一页纸回答以下问题。

- **核心体验：**希望玩家感受到什么？例如通过读招和走位掌握交锋节奏。
- **主要动作：**玩家每十几秒会反复执行哪些操作？
- **核心选择：**什么时候攻击、为什么闪避、何时承担风险？
- **变化来源：**靠敌人组合、场地、能力还是资源状态改变决策？
- **目标平台：**键鼠、手柄还是触屏？单次游玩大约多长？
- **目标玩家：**首次接触动作游戏，还是熟悉时机和连招的玩家？
- **视角和结构：**横版、俯视或第三人称？关卡制、箱庭还是其他结构？
- **原型边界：**这一轮只验证哪些问题，什么情况下算验证通过？

**示例目标：**玩家用轻击制造机会，用重击处理装甲，观察敌人前摇后选择闪避或追击。首轮只验证这三种选择是否成立，不以武器数量和关卡时长作为完成标准。

## 3 核心体验设计

### 3.1 输入与移动 P0

**需要设计什么：**起步、停止、转向、加速、冲刺，以及视项目需要加入的跳跃、攀爬和落地。定义攻击时能否转向或移动、闪避方向从何处取得、墙角和场地边界如何处理。同步确定输入缓存、长按与连按、按键优先级、失焦和暂停行为。

输入缓存是提前接收输入并在允许时执行；取消是提前结束当前动作进入另一动作。两者应分别设计，避免“能接下一招”被误写成“随时能取消”。

**建议产出：**操作映射表、移动参数表、动作状态转换图。跳跃项目另写土狼时间、跳跃预输入和可变跳高规则。

**如何验证：**先在空场地测试接近目标、急停、转身、闪避和边界碰撞。观察误操作、指令吞入、重复执行和角色卡住的情况。玩家应能稳定到达自己想去的位置。

### 3.2 战斗规则与决策 P0

**需要设计什么：**每个动作的前摇、有效期、恢复期、范围、位移、伤害、资源消耗、打断能力及可取消窗口。明确无敌、格挡、霸体、破防、硬直和击退的关系，以及同一攻击能否重复命中同一目标。

每个动作都应有使用理由。例如轻击提供较小承诺的试探，重击承担更长准备时间来换取破甲。若一种动作在伤害、范围、安全性和消耗上全面占优，其他动作通常很难形成有意义的选择。

**建议产出：**动作规格表、命中与防御规则表、连招及取消关系图。时间标明单位和基准，避免把渲染帧率当作动作规则。

**如何验证：**分别测试空挥、命中、被格挡、对装甲目标命中和双方同时攻击。检查玩家能否说明为什么选择某个动作，并观察是否出现无限压制、无限闪避或单一最优解。

### 3.3 敌人行为与遭遇 P0

**需要设计什么：**敌人的感知、接近、预警、出招、恢复、受击和死亡状态。为每类敌人指定战术职责，例如施压、限制走位、保护同伴或惩罚贪刀。提示需要能区分攻击方向、范围和危险时机。

群战还需要定义同时进攻数量、站位、进入攻击的条件，以及镜头外敌人的攻击限制或警告。敌人数量增加不能只意味着同时收到更多无法辨认的攻击。

**建议产出：**敌人行为图、招式表、遭遇组合表。Boss 另写阶段转换、可反击窗口，以及如何复用玩家已学会的规则。

**如何验证：**先单独验证每类敌人，再测试组合。观察玩家能否在几次尝试后解释攻击提示、找到反击机会，以及说明为什么先处理某个目标。

### 3.4 镜头与战斗可读性 P0

**需要设计什么：**镜头跟随、可视范围、遮挡处理、屏幕边缘行为，以及适用时的锁定与目标切换。规划角色、敌人、攻击提示、地形和特效的信息层级，保证视觉强度不会掩盖危险。

**建议产出：**镜头规则、遮挡处理方案、战斗信息层级和提示规范。

**如何验证：**测试贴边交锋、多敌人重叠、连续位移和强特效同时出现的场景。检查玩家是否因看不到攻击而受伤，以及缩小屏幕或关闭震屏后能否正常判断局面。

### 3.5 关卡与空间 P0 到 P1

**需要设计什么：**战斗区大小、通道宽度、高低差、障碍物、危险区、出入口和安全区。安排教学、练习、组合挑战、休息和奖励的节奏。探索项目还需要路线引导、捷径与回访价值。

场地应改变已有动作的使用条件。例如狭窄区域限制绕行，开放区域允许拉开距离；相应地需要检查敌人组合是否仍然公平。

**建议产出：**灰盒地图、遭遇分布图、关卡节奏表和关键路径说明。

**如何验证：**使用占位美术走完整流程，记录迷路、停顿、卡位、重复劳动和持续高压的位置。确认玩家理解当前目标，且场地不会让某个基础动作意外失效。

### 3.6 反馈与打击感 P0

**需要设计什么：**攻击预备与挥击表现、接触位置、受击反应、命中停顿、音效、特效和镜头反馈。区分挥空、普通命中、装甲命中、格挡、破防和击杀，保证反馈与实际规则相符。

**建议产出：**命中结果与反馈的映射表，以及反馈强度、频率和并发预算。

**如何验证：**在保持伤害、判定和敌人规则一致的条件下比较反馈，检查玩家能否辨认结果、保持操作和判断下一步。详细方法见 [打击感优化调研](../tutorial/impact-combat/docs/RESEARCH.md) 和 [设计方案与实现映射](../tutorial/impact-combat/docs/DESIGN.md)。

## 4 完整游戏所需的支撑设计

### 4.1 成长与构筑 P1

设计技能、装备、天赋、解锁和升级如何改变行动选择。明确操作水平与数值强度的关系，避免只有数值变大却没有新的决策。对带随机掉落的项目，需要定义掉落来源、重复物用途和构筑形成速度。

**产出与验证：**制作成长路径和能力比较表，使用同一组遭遇测试不同构筑。检查选择是否改变打法，是否出现必选项，以及旧能力是否被新数值完全替代。

### 4.2 资源与奖励 P1

区分战斗内资源和长期资源：体力、能量、弹药等影响当下决策；货币、材料和装备支持长期目标。定义来源、消耗、上限、恢复条件，以及失败后保留或损失什么。

**产出与验证：**列出资源流向和奖励节奏，试玩一段完整流程。检查玩家是否长期囤积不用、过早耗尽、被迫重复刷取，或拿到奖励却不知道用途。

### 4.3 难度与失败 P0 到 P1

定义挑战主要来自读招、反应、空间判断、资源管理还是数值。安排机制引入和组合难度，确定检查点、重试入口、失败损失和恢复资源。将“失败后重新学习”与重复跑图的时间成本分别评估。

**产出与验证：**制作难度曲线、检查点说明和失败规则。记录失败原因、重试耗时及放弃位置，优先处理看不懂、操作无响应和重试繁琐的问题，再调整敌人强度。

### 4.4 教学 界面与无障碍 P0 到 P1

通过安全尝试、单机制挑战和组合挑战逐步教学。界面需明确生命、资源、冷却、状态及目标；危险提示尽量同时利用形状、动作或声音，不仅依赖颜色。按平台考虑按键重映射、触控尺寸、文本大小、震屏强度和辅助选项。

**产出与验证：**制作首次游玩流程和界面状态表，让未接触项目的玩家独立试玩。记录需要口头解释的地方，检查关键提示在小屏、静音和减少动态效果时是否仍可理解。

### 4.5 游戏结构与内容生产 P1

定义单次游玩循环、关卡结束条件、存档、暂停、退出恢复和重复游玩的理由。估算一套敌人、一场遭遇和一个关卡的制作成本，再决定内容规模，避免关卡数量超过可验证的生产能力。

**产出与验证：**制作流程图、存档规则、内容清单和完成标准。验证一段从进入到退出再恢复的完整流程，并用实际制作记录修正工期估算。

### 4.6 叙事与世界 P1 或按项目目标提前

说明玩家为什么行动、敌人为什么出现，以及场景如何支持玩法。安排对白、过场与交互信息的出现时机，定义跳过、重试和重复游玩时的表现。以叙事为核心的项目需要在原型期验证它与行动节奏的关系。

**产出与验证：**制作关卡叙事节拍和触发规则，检查信息是否足够、是否频繁打断操作，以及重试时是否反复播放相同内容。

### 4.7 联机与长期运营 按项目目标决定

联机项目应尽早设计网络权威、命中确认、延迟容错、同步、断线和重连规则；合作模式还需考虑分工、复活、共享镜头和掉队。若项目有付费或运营目标，再设计解锁、内容更新与公平边界。

**产出与验证：**制作联机规则、异常流程和内容更新范围，在模拟延迟、丢包、离线和人数变化时验证核心玩法。不能只在本地无延迟环境下认定联机战斗成立。

### 4.8 性能与工具 P0 到 P1

明确目标设备、帧率和输入响应预算。低帧率、卡顿和高特效负载不应悄悄改变战斗规则；暂停、恢复和页面失焦也需要明确行为。为设计迭代提供判定显示、状态查看、参数调整和事件记录能力。

**产出与验证：**建立性能预算与调试入口，在目标设备和高负载场景中检查判定、计时、输入和提示。记录实际结果，再决定粒子、音效和敌人并发上限。

## 5 从原型到完整玩法的推进顺序

以下是适用于小型近战项目的推荐顺序，阶段应按验证结果推进，不必绑定固定天数。

| 阶段 | 最小内容 | 需要回答的问题 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| A 操作原型 | 空场、移动、基础攻击、防御动作 | 玩家能否准确控制角色？ | 输入、位移、边界和状态转换稳定 |
| B 单敌交锋 | 一个有预警和恢复期的敌人 | 观察和行动是否形成选择？ | 能说明失败原因并学会应对 |
| C 组合遭遇 | 两三种职责不同的敌人、简单场地 | 目标顺序和站位是否重要？ | 多次交锋中存在可理解的不同策略 |
| D 完整片段 | 教学、挑战、奖励、失败重试 | 循环能否连贯运行？ | 新玩家能独立完成并理解目标 |
| E 内容扩展 | 成长、更多敌人、关卡变化 | 新内容是否带来新决策？ | 核心规则稳定且制作成本可控 |

不要把“打击感强烈”单独视为阶段 B 通过。玩家还需要有可辨认的对手行为、行动机会和失败原因。

### 应用到 IMPACT LAB

当前项目已有移动、轻重攻击、闪避、装甲交互与反馈比较入口，可继续作为核心交锋的实验基础。以下为建议扩展项，不代表已经实现。

1. **先形成主动交锋：**加入一个可读的敌人主动攻击，验证预警、闪避和反击窗口。
2. **再验证敌人组合：**增加一个不同职责的敌人，观察站位和目标优先级是否改变。
3. **加入空间变化：**使用开阔与受限场地对照，测试边界、攻击范围和脱围机会。
4. **连接短流程：**安排首次教学、组合挑战、结束反馈和快速重试。
5. **最后评估成长需求：**只有当新的能力选择能改变交锋策略时，再扩展技能或装备。

每轮只解决明确的问题，保留当前反馈实验入口，以便比较新增规则对可读性和操作的影响。当前实现范围以 [实验 README](../tutorial/impact-combat/README.md)、[设计说明](../tutorial/impact-combat/docs/DESIGN.md) 为准；验证记录见 [VALIDATION.md](../tutorial/impact-combat/docs/VALIDATION.md)。

## 7 试玩与评审清单

试玩前写出待验证问题和通过条件，试玩中尽量让玩家独立行动。先记录行为，再询问原因，避免一边教学一边把结果当作易用性的证据。

### 核心体验

- [ ] 玩家能准确移动、转向和使用基础动作。
- [ ] 输入缓存、取消、无敌和打断遵守一致规则。
- [ ] 每个主要动作存在明确用途与代价。
- [ ] 玩家能够识别危险，并获得合理的应对机会。
- [ ] 命中、受伤、格挡和破防的反馈与实际结果一致。
- [ ] 多敌人和强特效场景仍然可读。
- [ ] 场地和敌人组合会改变玩家的选择。

### 完整流程

- [ ] 玩家理解当前目标及基本资源用途。
- [ ] 教学允许玩家亲手尝试，不依赖开发者口头解释。
- [ ] 失败后能理解原因，并快速重新尝试。
- [ ] 成长或奖励带来可理解的价值。
- [ ] 存档、退出恢复、暂停和失焦行为符合预期。
- [ ] 目标设备上的输入、判定、计时与提示稳定。
- [ ] 辅助选项不会遮蔽关键提示或破坏基础操作。

### 如何记录与修正

| 观察项 | 建议记录 | 用途 |
| --- | --- | --- |
| 动作选择 | 使用场景、次数、命中与空挥 | 发现动作缺少用途或全面占优 |
| 受伤与失败 | 来源、位置、当时动作、玩家解释 | 区分读招、输入、镜头和数值问题 |
| 关卡推进 | 停顿位置、迷路、重试耗时 | 调整引导与失败成本 |
| 资源与成长 | 获取、消耗、囤积、升级选择 | 检查奖励节奏和构筑价值 |
| 性能与设备 | 帧率变化、卡顿、设备与输入方式 | 定位技术条件对体验的影响 |

不要只比较通关率或平均分；不同玩家经验和测试条件会影响结果。比较反馈方案时保持规则一致，比较规则时尽量保持表现一致，并记录仍存在的变量。

每个问题按下面的格式收尾，避免只留下“手感不好”这样的结论。

```text
问题与复现条件：
观察证据与玩家反馈：
可能原因：
本轮修改及预期影响：
复测条件与实际结果：
是否通过及后续处理：
```
