# 动作游戏打击感优化

沿着「输入 → 蓄势 → 释放 → 接触 → 目标回应 → 战斗结果」诊断。玩家应能判断：动作由我发起、攻击确实命中、这一击改变了什么、何时可以做下一步。

## 工作边界与项目入口

根据请求选择调研、诊断或实现；调研请求输出结论和候选实验，只有请求实现时修改玩法或表现。使用本 Skill 本身不授予提交、推送、发布或外部消息权限，沿用当前会话已有授权。

按问题读取相关文件，不必加载全部资料：

- 攻击数据、剑刃姿态、扫掠碰撞与阻尼弹簧：[combat.js](../../../combat.js)。
- 输入缓存、状态转换、计时、音频与场景绘制：[game.js](../../../game.js)。
- 当前玩法和参数：[设计方案](../../../docs/DESIGN.md)。以实现为准，发现文档过期时同步修正。
- 外部证据、诊断理由和候选实验：[优化调研](../../../docs/RESEARCH.md)。区分正文依据、视频入口、代码推算与体验假设。
- 已验证行为及限制：[验证记录](../../../docs/VALIDATION.md)。

## 优化时保留的关键约束

- 做反馈对比时，保持同一攻击的伤害、几何、击退、硬直和装甲规则一致。调整缓存、取消窗口或攻击数据属于玩法改变，应明确报告，避免把胜率变化归因于粒子或震屏。
- 近战武器绘制和碰撞共用姿态，在有效窗口内扫掠，并让每目标每次攻击只结算一次。允许合理的判定宽容，但需要解释实体剑刃、剑气与碰撞范围的对应关系。
- 先记录碰撞位置，再应用击退；接触火花留在接触点，伤害数字、受击动画可跟随目标。
- 明确真实经过时间、战斗模拟时间和表现时间。停顿可冻结指定的战斗状态；试炼倒计时单独计时。固定步长配合有上限的补步，写明长卡顿和后台隐藏时的策略。
- 区分设定停顿、模拟中实际冻结时长、渲染可见时长与音频输出延迟。当前 `stop-end.observed` 来自战斗时钟，不能当作现实时间或端到端输入延迟。
- 输入缓存定义接受、过期、覆盖优先级和消费窗口。当前项目使用单槽缓存，闪避优先；攻击中保留预输入，不能无限排队或跳过命中前的承诺。
- 轻击、重击、装甲承受、破防与终结需要不同重音。先调接触清晰度，再调反馈强度；避免全部事件都使用最大停顿、粒子量和音量。
- 镜头优先考虑方向性冲量与阻尼回弹；多声部音效设置重要性和并发预算。保留独立开关和低动态选项，尊重系统减少动态效果偏好。

## 诊断和迭代方法

1. 用一种攻击、一个目标、相同站位复现。记录问题是晚、轻、穿透、丢指令、过度刺激还是看不清下一步。
2. 关闭表现通道，检查玩法结果。命中停顿会改变现实时间内的攻击次数，不能直接比较不同预设的试炼分数来判断打击感。
3. 检查输入、剑刃接触、碰撞结算、火花、目标反应与声音是否对应同一事件。用判定显示检查背向、边缘范围、移动穿越与有效帧。
4. 按问题选择最小改动；每次只改变一个因素。当前候选测试水平为重击停顿 50/80/90/110 ms、缓存 120/180/240 ms。这些是本原型的试验范围，不是通用最优值。缓存时长修改需同时检查“攻击中寿命是否推进”。
5. 分别评价命中辨识、力量可信度、下一步可操作性和疲劳。短时“更强烈”与连续战斗“更好用”分别记录，未经用户实验的判断标为设计假设。
6. 涉及战斗规则或计时变更时运行下述回归；为实际修复的缺陷补充有意义的行为测试。文档或低风险样式调整只做相应检查，不机械重复整套测试。

## 按症状定位

| 症状 | 优先检查 |
| --- | --- |
| 挥剑却没打中，或隔空扣血 | 绘制与判定是否共用姿态、有效窗口、扫掠采样、目标边界和去重 |
| 打中却没重量 | 蓄势与释放速度差、接触阻力、受击方向、击退过程、装甲承受反馈 |
| 连招或闪避不跟手 | 缓存覆盖、到期规则、命中停顿冻结、收招／取消条件、冷却 |
| 不同帧率下手感不同 | 累加器、丢弃时间、固定步长、计时域、渲染和模拟的先后关系 |
| 震动晕、声音糊 | 镜头峰值和回弹、声部并发与重复触发、重音层级、敌人预警是否被遮挡 |
| 手机一按出两招 | pointerdown 与兼容 click 去重、键盘与辅助技术激活是否仍可用、长按移动与释放 |

## 本项目验证入口

从仓库根目录运行已有行为测试与语法检查：

```sh
node --test tests/combat.test.cjs
node --check game.js
node --check combat.js
```

计时或碰撞修改重点覆盖 20/30/60/144 fps、单次结算、左右镜像、挥空、三连、三次重击破甲及 30 秒试炼；原始与完整预设比较相同伤害和接触几何。

浏览器使用已有本地服务；尚无服务时运行 `python3 -m http.server 4173 --bind 127.0.0.1`。检查键盘与触控、单次点击、按住移动、释放／失焦、控制台和窄屏布局。需要自动化时使用当前环境可用的浏览器工具，不把本机浏览器绝对路径写进可复用说明。

展开「接触与节奏实验」调整停顿、显示判定、导出本轮记录；以 `?debug=1` 打开时通过只读 `window.impactLab.snapshot()` 检查状态。事件日志只保留最近 120 条，应及时导出；模拟测试与真实硬件测量分开报告。
